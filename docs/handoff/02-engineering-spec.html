Purpose, and the floors

PURPOSE OF RECORDCollect information confidentially within the attorney-client relationship. Prepare materials privately for counsel. Require an authorized disclosure decision before anything is released outside that protected workflow. The attorney decides whether to use the exhibits and how.

Three planes fall out of that sentence, and the schema, the permissions and the export path all follow the planes. Evidence plane: the thread and its log. Intelligence plane: everything derived from it for counsel. Disclosure decision: the one gate anything passes through to leave.

Floors: enforced by the application, never configurable

IdFloorEnforced where
F-01Written before read. No model call on a message that is not already durably committed to the firm-scoped log.Write path (§2). Selector is invoked only by a post-commit job.
F-02The client-facing model has no tools, no network, no database handle, and no case file. Its only input is the evidence plane rows for one case; its only output is a prompt id plus slot values.Selector interface (§3). Structural, not prompt-based.
F-03Intelligence-plane tables are unreachable from the selector and validator code paths.DB roles; separate service account with no grants on derived_*, flags, dispositions.
F-04Row-level security by firm and matter on every table.Postgres RLS policies; tested in §8.
F-05The model never authors a human class. attorney_communication rows are written only by an authenticated human session.Insert trigger checks author_type against session identity.
F-06No outbound channel except the client's own number on the firm's line. No email, no insurer, no provider, no export from the agent path.Twilio send restricted to cases.client_number; no other egress in the agent service.
F-07Never discusses liability; never answers legal, medical, case-status or insurance questions. At Levels 0–2 this is a property of the library; at 3–4 it is a validator rejection.Library contents; validator prohibited-topic classifier (§3).
F-08Safety escalation cannot be disabled.No config key exists for it.
F-09No message bodies in notifications, analytics, or error logs.Notification payload schema has no body field; log scrubber; no product analytics.
F-10Nothing is deleted. Corrections annotate. Litigation hold blocks every deletion path including retention jobs.Append-only tables; REVOKE DELETE, UPDATE on log; hold flag checked by retention job.
F-11Disclosure names the attorney and nothing captures before consent.Notice state machine (§2); capture disabled unless DISCLOSED_CONSENTED.
F-12Every outbound message is logged with class, library id (if any), hash-chain link and timestamp, before Twilio is called.Write path (§2).

Data model

Postgres, one schema per plane. Names are working names. Everything the POC already has can be mapped onto this; where it differs, the spec wins unless the dev says why.

Evidence plane (ev.*) — append-only

-- The log. One row per message or system event. Never updated, never deleted.
create type ev.message_class as enum
  ('agent_prompt','client_statement','attorney_communication','system_event');
create type ev.author_type as enum ('agent','client','attorney','staff','system');

create table ev.log (
  log_id          bigserial primary key,          -- LOG-#### is a display form of this
  firm_id         uuid not null,
  case_id         uuid not null,
  seq             integer not null,               -- contiguous per case, 1..n
  at_utc          timestamptz not null,
  at_local        timestamp not null,             -- client-local, for the exhibit
  tz              text not null,
  message_class   ev.message_class not null,
  author_type     ev.author_type not null,
  author_id       uuid,                           -- human session for attorney/staff rows
  author_label    text not null,                  -- exactly what the client saw, e.g. "Sara Alvarez (your attorney)"
  library_id      text,                           -- P-10a etc.; required when author_type='agent'
  protocol_version text not null,                 -- pinned at case open
  body            text not null,
  media_id        uuid references ev.media_vault,
  twilio_sid      text,                           -- inbound/outbound message sid
  prev_hash       bytea not null,                 -- hash of previous row for this case (genesis = direction letter hash)
  row_hash        bytea not null,                 -- sha256(prev_hash || canonical(row))
  tsa_token       bytea,                          -- RFC 3161 token, filled by anchor job (§2)
  tsa_at          timestamptz,
  unique (case_id, seq),
  check ((author_type='agent') = (library_id is not null or protocol_version like '%L3%' or protocol_version like '%L4%'))
);
revoke update, delete on ev.log from public;    -- and from every app role

create table ev.media_vault (                    -- sealed originals; derivatives live elsewhere
  media_id uuid primary key, case_id uuid not null, kind text check (kind in ('voice','photo','video')),
  object_key text not null, sha256 bytea not null, bytes bigint, received_at timestamptz not null,
  transcript_log_id bigint                       -- the derivative it was attached to, if any
);

create table ev.consent (                        -- disclosure version consented to; also a system_event row
  case_id uuid primary key, disclosure_version text not null, disclosure_hash bytea not null,
  consented_at timestamptz not null, log_id bigint not null references ev.log
);

create type ev.notice_state as enum
  ('NOT_STARTED','DISCLOSED_PENDING','DISCLOSED_CONSENTED','PAUSED','STOPPED','CLOSED');

-- Direction: the attorney's elections + the library, hashed together.
create table ev.direction_letter (
  letter_id uuid primary key, case_id uuid not null, attorney_id uuid not null,
  protocol_version text not null, autonomy_level smallint not null check (autonomy_level between 0 and 4),
  approval_regime text not null,                 -- library | per_message | first_n_days | post_hoc
  elections jsonb not null,                      -- mode, cadence, topics, photo election, forum, escalation
  letter_hash bytea not null, authorized_at timestamptz not null, superseded_by uuid
);
create table ev.protocol_version (version text primary key, library jsonb not null, rules jsonb not null, approved_by uuid, approved_at timestamptz);

Intelligence plane (iq.*) — derived, asserted item by item

create table iq.derived (                        -- timeline entries and structured fields
  derived_id bigserial primary key, case_id uuid not null,
  field text not null,                           -- pain_back, function, work, treatment, ...
  value jsonb not null,
  event_at text,                                 -- as stated by the client, or 'not stated'; never estimated
  reported_at timestamptz not null,
  asserted_by text not null default 'client',
  source_log_ids bigint[] not null check (cardinality(source_log_ids) > 0),
  location_stated boolean not null,              -- false = unlocated; never assigned to a region
  model_version text not null, prompt_version text not null, generated_at timestamptz not null,
  candidate_pathways jsonb                       -- per pinned jurisdiction pack; labels, never "admissible"
);

create type iq.flag_type as enum ('TREATMENT_GAP','NON_RESPONSE','NEW_PROVIDER','MED_CHANGE','WORK_ACTIVITY',
  'QUESTION_FOR_HUMAN','LIABILITY_CONTENT','INCONSISTENCY','THIRD_PARTY_CONTACT','SOCIAL_MEDIA',
  'PRIOR_CONDITION','SYMPTOM_ESCALATION','SAFETY','STOP_OR_PAUSE','NO_FIT');
create type iq.urgency as enum ('routine','same_day','immediate');
create type iq.route as enum ('paralegal','attorney','both');

create table iq.flag (
  flag_id bigserial primary key, case_id uuid not null, type iq.flag_type not null,
  urgency iq.urgency not null, routed_to iq.route not null,
  source_log_ids bigint[] not null, raised_at timestamptz not null, model_version text not null
);
create table iq.disposition (                    -- one required per flag; attorney rows are counsel's impressions
  disposition_id bigserial primary key, flag_id bigint not null references iq.flag,
  actor_id uuid not null, actor_role text not null check (actor_role in ('attorney','paralegal')),
  action text not null,                          -- noted | thought | escalate | ack | resolved
  note text, at timestamptz not null
);
create table iq.digest (digest_id bigserial primary key, case_id uuid, week_start date, body jsonb, generated_at timestamptz not null);
create table iq.receipt (                        -- passive: opening a digest, case or thread
  receipt_id bigserial primary key, case_id uuid not null, actor_id uuid not null, actor_role text not null,
  surface text not null check (surface in ('digest','thread','case','queue')), ref_id bigint, at timestamptz not null,
  check (surface <> 'digest' or ref_id is not null)  -- a digest receipt must name a digest that exists and predates it (§8)
);
create table iq.election (                       -- the disclosure decision
  election_id uuid primary key, case_id uuid not null, attorney_id uuid not null,
  scope text not null check (scope='whole_record'),  -- no partial scope exists
  purpose text not null, review_id uuid not null,   -- impeachment-surface review that preceded it
  export_manifest jsonb not null, at timestamptz not null
);
REQUIREMENT R-1Every iq.derived row cites at least one ev.log row (enforced), and a located score cites a row whose body names the region (checked in CI against the demo case, §9). event_at is text so that "not stated" is a legal value; the structuring job must never fill it with an estimate.

The write path

IdRequirementPasses when
R-2Inbound webhook verifies the Twilio signature and rejects on failure without writing.Forged request → 403, no row.
R-3Inbound from a number whose case is not DISCLOSED_CONSENTED is logged as system_event ("message received before consent") and not processed; STOP transitions to STOPPED; a question routes to the paralegal.State table matches §2 of the case-flow doc; test corpus in §8.
R-4Hash chain: row_hash = sha256(prev_hash ‖ canonical_json(row minus hash fields)); genesis prev_hash is the direction letter hash. Canonicalization is documented and versioned.Recompute over the demo case; a single altered byte breaks the chain from that row on.
R-5RFC 3161 anchoring: batched, asynchronous, every row anchored within 10 minutes; anchor failure raises an operational alert and never blocks the write.Kill the TSA in test; writes continue; alert fires; backlog anchors on recovery.
R-6Media: fetched from Twilio promptly, sealed to the vault (hash, object key), deleted at Twilio, transcript derivative attached to a client_statement row; the sealing is a system_event row.Vault hash matches original; Twilio media gone after fetch.
R-7Outbound messages are written (step 6) before send (step 7); the Twilio sid is stored on the existing row afterwards. Send failure is a system_event, never a missing row.Kill Twilio in test; row exists with failure event.

3

The agent turn at Level 2

The selector chooses; the validator decides whether the choice may be sent. Neither composes text at Level 2. The library and rules are the pinned protocol version (currently v1.4, in the demo case). The selector may be a model; the validator is code plus, at Levels 3–4, a separate model with an allowlist role.

IdRequirementPasses when
R-8The selector service account has grants on ev.log (select, case-scoped), ev.protocol_version (select) and nothing else. No network egress except the model endpoint.Grant audit; egress firewall rule; attempt to query iq.* fails.
R-9Slot rendering is template substitution only. The selector returns ids and slot strings; the application renders the library text. No model output is ever sent verbatim at Levels 0–2.Code review; fuzz the selector output with free text and confirm none reaches Twilio.
R-10Validator checks V1–V8 are implemented as pure functions over (proposed turn, case log, protocol rules, clock) and unit-tested against the demo thread: every one of its 52 agent rows passes; each injected violation fails the named check.Test suite green; violation table in §8.
R-11Post-appointment triggers fire 2 hours after an appointment entered by staff; scheduled openers fire at the elected cadence; the client-initiated path is always open. Cadence and triggers are per-case elections in the direction letter.Replay the demo calendar; the 13 openers and 7 triggers fire at the logged times.
R-12Non-response: after one unanswered opener and one P-40 nudge, the agent stops and raises NON_RESPONSE to the paralegal. No further agent messages until a client message or a human resumes.Demo days Mar 18–20 reproduce: 4 prompts, then silence, then flag.

Autonomy levels and approval regimes

LevelWhat the agent may doModel placementDefault regime
0 · RelayNothing. Sends messages counsel wrote.None—
1 · QuestionnaireSends counsel's fixed questions on cadence. No follow-ups.None (or in-tenant for scheduling only)Library
2 · Library DEFAULTSelects from the library; fills sourced slots; raises flags; drafts digest. Composes nothing.In-tenant selector, or zero-retention enterpriseLibrary approval at setup; post-hoc receipt
3 · BoundedGenerates follow-ups that pass a neutral-prompt validator model with an allowlist role.Zero-retention enterprise; validator separate from generatorFirst-N-days review (N=14) then post-hoc

REQUIREMENT R-13Level and regime are columns on the direction letter, enforced server-side on every agent turn (a Level 2 case cannot receive generated text even if the selector returns it). Changing level, pausing, or turning off writes a new direction_letter row that supersedes the old one, and a system_event in the log. Per-message and first-N-days regimes hold the agent row in a pending state that is not sent until an attorney approves; the approval is a disposition-like row with actor and time.

Intelligence plane

Structuring job

Runs after each committed client row. Writes iq.derived rows with dual dating, asserted_by, source ids, generation metadata, and location_stated. Its outputs are checked in CI against the demo case (§9). It never modifies the log.

REQUIREMENT R-14Every flag requires exactly one or more iq.disposition rows before it leaves the attorney's or paralegal's queue. Flags are never deleted. Attorney dispositions offer three actions: noted, thought (with note), escalate (opens the thread composer as the attorney). Push delivery of evidentiary flags carries type, case, and a deep link; never the body (F-09).
REQUIREMENT R-15Receipts are passive: opening a digest, the thread, or the case writes an iq.receipt row. A digest receipt must reference a digest whose generated_at precedes the receipt. Digests are drafted weekly per case and never auto-sent outside the firm.

Export and the disclosure decision

Nothing leaves the workflow except through iq.election, and an election is of the whole record. The packaging engine renders the evidence plane plus derived rows into exhibits under the pinned jurisdiction pack, with candidate-pathway labels and never the word "admissible."

IdGate or rulePasses when
R-16Export requires attorney role and a completed impeachment-surface review (review_id) that surfaced every adverse entry (the demo case §6 list) before the election could be recorded.Paralegal cannot export; attorney cannot export without a review row.
R-17No partial scope exists. There is no UI or API to export a subset of client statements. Redaction of another person's PHI is an annotation on the export manifest, not a deletion.Schema check constraint; API returns 400 on any scope other than whole_record.
R-18Warnings fire, with acknowledgement logged, on: sending the transcript to the client (§771), sharing with an expert, exporting while notice state for the certification route is not NOTICE_SERVED.Each warning path logs an acknowledgement event with actor and time.
R-19Certification readiness state machine: CERTIFICATION_ELIGIBLE → NOTICE_NOT_SERVED → NOTICE_SERVED → OBJECTION_RECEIVED → LIVE_FOUNDATION_REQUIRED. The engine refuses to label a certification route as ready outside NOTICE_SERVED.State tests.
R-20Custodian certification recites system operation only (mode of preparation, regular course, hash chain, anchoring), never what any chronology shows.Template review; no case facts in the template.
R-21Supervision record export: one action produces the document in handoff 3 from direction_letter, consent, receipt, disposition, election and change events.Demo case produces the values shown in handoff 3.
R-22CMS: push-only, of finalized exhibits and administrative milestones; no inbound endpoint; idempotency keys; failures visible in the workbench; capture never depends on the CMS being reachable.CMS down → capture continues; queue drains on recovery; no duplicates.

REQUIREMENT R-23 · PLAINTEXT SURFACE DOCUMENTThe dev writes and maintains one page listing every place a message body exists in the clear during ordinary processing and support: application memory, the model call, the speech-to-text call, the webhook handler, logs (should be none), break-glass. For each: who can see it, for how long, and what audit exists. Customer-managed keys protect data at rest; they do not make compelled vendor production ciphertext, and this document is what counsel needs to say what the vendor can actually produce.
REQUIREMENT R-24 · RETENTION AND HOLDFirm-elected retention per case, applied by a job that checks hold first and logs every deletion as a system_event in an archive table. Vendor-side minimization (Twilio, STT) is a separate schedule from the firm's duty to preserve, and both are documented.

First integration test: load the demo case

docs/demo-case/thread.json is 107 rows of a synthetic thirty-day case at Level 2, generated from the reviewed Markdown by web/scripts/build-demo-case.py. Loading it is the first end-to-end audit of the POC.

  1. Ingest the 107 rows in order as if they had arrived live (client rows through the webhook path, agent rows through the send path with the selector stubbed to return the recorded library_id and slots).
  2. Confirm counts: 48 client, 52 agent, 4 human, 3 system; seq contiguous 1–107; every agent row carries a library id from protocol v1.4.
  3. Recompute the hash chain and verify; anchor and verify tokens.
  4. Run the validator over every recorded agent turn: all 52 pass. Run the §8 violation table: each fails the named check.
  5. Run the structuring job and diff against docs/demo-case/timeline.md §1–2: the 46 entries and the pain series, with unlocated scores unlocated and unstated times unstated.
  6. Confirm the nine flags in timeline.md §3 are raised with the stated types, routes and urgencies.
  7. Record the receipts in §4 and produce the supervision record; compare to handoff 3.
  8. Attempt every refusal in §8 against the loaded case.
REQUIREMENT R-25The demo-case fidelity checker (refs exist, series values in cited rows, located scores name a region, receipts after drafts, sourced slots verbatim, no repeat questions) is ported into the structuring and validator test suites and runs in CI on every change.
